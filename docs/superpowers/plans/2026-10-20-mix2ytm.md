# mix2ytm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `mix2ytm <url>` CLI that saves every video of a YouTube Mix as a private YouTube Music playlist.

**Architecture:** One TypeScript file run directly by Node 22. It shells out to `yt-dlp` to list the Mix, then makes one authenticated `POST youtubei/v1/playlist/create` to YT Music using the user's browser cookie. Pure helpers are exported and covered by `node --test`; the network parts are verified by real runs.

**Tech Stack:** Node 22.23 (built-in type stripping), `node:test`, `yt-dlp` (`/opt/homebrew/bin/yt-dlp`). No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-20-mix2ytm-design.md`

## Global Constraints

- Root: `~/my-tools/mix2ytm/`. Files: `package.json`, `mix2ytm.ts`, `mix2ytm.test.ts` only.
- No npm dependencies, no build step, no `tsconfig.json`. Only erasable TS syntax (no `enum`, `namespace`, parameter properties) so Node's type stripping runs it.
- `package.json`: `"type": "module"`, `"bin": { "mix2ytm": "./mix2ytm.ts" }`, `"scripts": { "test": "node --test" }`.
- `mix2ytm.ts` starts with `#!/usr/bin/env node`, and is `chmod +x`.
- `main()` runs only when executed directly: `if (realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)) main()`. Use realpath because `npm link` runs the file through a symlink. Tests import the module without running `main`.
- Cookie path: `~/.config/mix2ytm/cookie`. Origin: `https://music.youtube.com`. Privacy: `PRIVATE`. Description: `Converted from <url>`.
- `~/my-tools` is not a git repo: skip all commit steps.

## Review Focus

1. **Cookie pasted with a `Cookie: ` prefix or a trailing newline.** It should still parse. Test in Task 1.
2. **Unavailable videos in the Mix** (`[Private video]` / `[Deleted video]` titles). Drop them with a printed note so `create` doesn't fail. Test in Task 2.
3. **Link without a playlist** (plain `watch?v=` link: yt-dlp JSON has no `entries`). Exit with `No videos found in this link`, not a crash. Test in Task 2.
4. **Bad `--limit`** (`abc`, `0`, `-3`). Exit with a usage error, not "take 0 videos". Test in Task 2.
5. **Very large Mix (~437 IDs) in one `create` call.** The spec requires a real-run check, with the fallback described in Task 3.

### Task 1: Scaffold + auth helpers

**Files:**
- Create: `package.json`, `mix2ytm.ts`
- Test: `mix2ytm.test.ts`

**Interfaces:**
- Produces: `sapisidFromCookie(cookie: string): string | undefined`, `authHeader(sapisid: string, ts: number): string`

- [ ] **Step 1: Write the failing tests** in `mix2ytm.test.ts` (`import test from 'node:test'`, `import assert from 'node:assert/strict'`, `import { createHash } from 'node:crypto'`):
  - `sapisidFromCookie('a=1; SAPISID=xyz; __Secure-3PAPISID=other')` → `'xyz'`
  - `sapisidFromCookie('a=1; __Secure-3PAPISID=other')` → `'other'`
  - `sapisidFromCookie('a=1; b=2')` → `undefined`
  - `sapisidFromCookie('Cookie: SAPISID=xyz; a=1\n')` → `'xyz'` *(Review Focus 1)*
  - `authHeader('abc', 1700000000)` → `'SAPISIDHASH 1700000000_' + createHash('sha1').update('1700000000 abc https://music.youtube.com').digest('hex')`
- [ ] **Step 2: Run** `cd ~/my-tools/mix2ytm && npm test`. Expected: FAIL (module/exports missing).
- [ ] **Step 3: Implement** `package.json` (see Global Constraints) and the two helpers in `mix2ytm.ts`. Before parsing, `sapisidFromCookie` trims the string and strips a leading case-insensitive `cookie:`. It then splits on `;` and trims each `name=value` pair. Add an empty `main()` with the realpath guard. Run `chmod +x mix2ytm.ts`.
- [ ] **Step 4: Run** `npm test`. Expected: 5 passing.

### Task 2: Read the Mix (CLI args + yt-dlp + `--dry-run`)

**Files:**
- Modify: `mix2ytm.ts`
- Test: `mix2ytm.test.ts`

**Interfaces:**
- Produces:
  - `parseCli(argv: string[]): { url: string; limit?: number; title?: string; dryRun: boolean }`. Throws `Error` with the usage text on a missing URL or bad limit.
  - `type Track = { id: string; title: string }`
  - `parseMix(json: string): { title: string; tracks: Track[] }`. Throws `Error('No videos found in this link')` when there are no entries.
  - `readMix(url: string, limit?: number): { title: string; tracks: Track[] }`, which calls yt-dlp and then `parseMix`.

- [ ] **Step 1: Write the failing tests**:
  - `parseCli(['https://x'])` → `{ url: 'https://x', limit: undefined, title: undefined, dryRun: false }`
  - `parseCli(['https://x', '--limit', '5', '--title', 'T', '--dry-run'])` → `{ url: 'https://x', limit: 5, title: 'T', dryRun: true }`
  - `parseCli([])`, `parseCli(['u', '--limit', 'abc'])`, `parseCli(['u', '--limit', '0'])` each throw *(Review Focus 4)*
  - `parseMix(JSON.stringify({ title: 'Mix - A', entries: [{id:'a',title:'A'},{id:'b',title:'B'},{id:'a',title:'A'}] }))` → `{ title: 'Mix - A', tracks: [{id:'a',title:'A'},{id:'b',title:'B'}] }` (dedupe, order kept)
  - `parseMix` drops entries titled `[Private video]` or `[Deleted video]` *(Review Focus 2)*
  - `parseMix(JSON.stringify({ title: 'one video', id: 'x' }))` and `parseMix(JSON.stringify({ title: 'Mix', entries: [] }))` throw `/No videos found/` *(Review Focus 3)*
- [ ] **Step 2: Run** `npm test`. Expected: the new tests FAIL.
- [ ] **Step 3: Implement**:
  - `parseCli`: `util.parseArgs` with `allowPositionals: true` and options `limit` (string), `title` (string), `dry-run` (boolean). `limit` must be `/^\d+$/` and > 0.
  - `parseMix`: as specified. Log dropped unavailable videos to stderr.
  - `readMix`: `execFileSync('yt-dlp', ['--flat-playlist', '-J', ...(limit ? ['--playlist-end', String(limit)] : []), url], { encoding: 'utf8', maxBuffer: 64 * 1024 * 1024 })`. Turn `ENOENT` into `Error('yt-dlp not found — brew install yt-dlp')`. On any other failure, rethrow with yt-dlp's stderr.
  - `main`: parse args, read the Mix, print `i. <title>` per track and then `<n> tracks`. Stop if `dryRun`. Catch all errors: `console.error(err.message)`, `process.exit(1)`.
- [ ] **Step 4: Run** `npm test`. Expected: all pass.
- [ ] **Step 5: Verify against the real Mix**:
  - `./mix2ytm.ts 'https://www.youtube.com/watch?v=0GVExpdmoDs&list=RD0GVExpdmoDs&start_radio=1' --dry-run` → numbered list starting `1. Maroon 5 - Animals (Lyrics)`, roughly 437 tracks.
  - Same with `--limit 5` → exactly 5 tracks.
  - `./mix2ytm.ts` with no args → usage, exit code 1.

### Task 3: Create the playlist + install

**Files:**
- Modify: `mix2ytm.ts`

**Interfaces:**
- Consumes: `sapisidFromCookie`, `authHeader` (Task 1); `readMix`, `parseCli` (Task 2).
- Produces: `createPlaylist(cookie: string, title: string, description: string, videoIds: string[]): Promise<string>` (returns `playlistId`).

- [ ] **Step 1: Implement `createPlaylist`.** Follow the spec's *Flow §5* exactly (URL, headers, body).
  - `clientVersion`: `` `1.${YYYYMMDD of today}.01.00` ``.
  - `sapisidFromCookie` returns undefined → `Error('Cookie is missing SAPISID — copy it again')`.
  - HTTP 401/403 → `Error('Cookie expired or invalid — copy it again')`.
  - Other non-2xx, or no `playlistId` in the response → `Error` with the status and the response body.
- [ ] **Step 2: Wire into `main`** after the dry-run check:
  - Read the cookie with `readFileSync(join(homedir(), '.config/mix2ytm/cookie'), 'utf8')`. On `ENOENT`, throw an error whose message is the spec's one-time setup steps.
  - Title is `cli.title ?? mix.title`.
  - Print `https://music.youtube.com/playlist?list=<id>`.
- [ ] **Step 3: Run** `npm test`. Expected: still all pass (Tasks 1–2 tests).
- [ ] **Step 4: Verify the missing-cookie path.** With no `~/.config/mix2ytm/cookie`, run `./mix2ytm.ts '<example url>' --limit 3`. Expected: setup instructions, exit 1.
- [ ] **Step 5: User does the one-time cookie setup** (spec *Usage*). The implementer must ask the user to do this; never read browser cookie stores.
- [ ] **Step 6: Real run, small.** `./mix2ytm.ts '<example url>' --limit 5 --title 'mix2ytm test'` prints a playlist link. The user confirms it opens in YT Music with 5 tracks.
- [ ] **Step 7: Real run, full Mix** *(Review Focus 5)*. Run `./mix2ytm.ts '<example url>'`. The user confirms the playlist holds about the same count as the dry run.
  - **If `create` rejects the large list:** create with the first 100 IDs, then add the rest in chunks of 100. Use `POST https://music.youtube.com/youtubei/v1/browse/edit_playlist?prettyPrint=false` with body `{ context, playlistId, actions: ids.map(id => ({ action: 'ACTION_ADD_VIDEO', addedVideoId: id })) }`, then re-run this step.
- [ ] **Step 8: Install.** `cd ~/my-tools/mix2ytm && npm link`, then `mix2ytm '<example url>' --limit 3 --dry-run` from another directory.
  - If it fails with a type-stripping error under `node_modules`: `npm unlink -g mix2ytm`, then tell the user to add `alias mix2ytm='node ~/my-tools/mix2ytm/mix2ytm.ts'` to `~/.zshrc`.
